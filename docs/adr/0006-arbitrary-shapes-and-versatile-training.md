# 0006. 任意图形内容层与「全能」训练口径

- 状态：已接受
- 日期：2026-10-22
- 相关：[ADR-0002](0002-online-trajectory-over-offline-images.md)（联机轨迹优先）、
  [ADR-0003](0003-cpp-core-python-for-training.md)（C++ 核心 / Python 训练）

## 背景

产品诉求从「复刻手写字」扩展到「**不只是字，任何奇形怪状都要能写**」——
思维导图、教案表格、示意图、箭头等，并且希望模型「全能」一点，而不是只会写汉字。

需要回答两个问题：

1. 非文字内容如何进入现有「轨迹 → G 代码 → 机器」的管线？
2. 「全能」在训练层面意味着什么？是不是要给每类内容各训一个模型？

## 决策

### 1. 不新增渲染 / G 代码分支，只新增「内容层」

管线在 `Stroke` 层已经是**图形无关**的：`StrokeSet`（归一化 0~1、y 向下）是唯一契约，
`render → layout → gcode → preview` 都只认它。一个汉字、一张表格、一段 SVG 路径，
在下游看来没有区别。因此：

- **不**为非文字内容另写一套 G 代码生成或预览（否则预览与实机必然漂移）；
- 只新增一个**内容层**，负责把各种输入都变成 `StrokeSet`。

### 2. `src/handwriting/shapes.py` —— 内容层

- 几何基元：`line_segment / rect_outline / circle / ellipse / arrow / polyline`
- 结构化生成：`compose_table(rows, cols, texts)`、`compose_mindmap(nodes, edges)`
- **通用适配器**：`svg_to_stroke_set(svg)`，解析
  `path / line / polyline / polygon / rect / circle / ellipse`，路径支持
  `M L H V C S Q T A Z`（含相对坐标与椭圆弧按角度采样）

### 3. `src/handwriting/sheets.py` —— 编排

`ShapeSheet` 把若干 `StrokeSet` 按近正方形网格（`cols ≈ √count`）摆进 `Page`，
复用 `glyphs_to_gcode_with_stats` 与 `preview.to_svg`。版面数学与文字排版共用，
所以预览就是实机走位。

### 4. 采集器「图形」模式

`capture/index.html` 新增「图形」模式：自由绘制任意图形，导出仍是
`handwriting-capture/2.0`，但标记 `meta.contentType = "shape"`、
`lines[].kind = "shape"`、`text = ""`。图形数据与整行数据在 `Stroke` 层面完全相同，
一份 `LineCapture` 读取器即可两用。

### 5. 训练口径：单一「笔尖动态先验」，而非逐字字形模型

所有采集（1.0 单字、2.0 整行、2.0 图形）本质都是**同一种东西**：一段带时序、压感、
抬落笔的笔尖轨迹序列。因此「全能」的实现方式不是给每类内容训一个模型，而是：

> 训练一个**条件于目标中心线**的笔迹动态模型 ——
> 输入任意中心线（汉字骨架 / 表格边框 / SVG 路径），
> 输出「这个人」在这个中心线上的书写动作（速度、压感、抖动、连笔、抬落笔节奏）。

逐字模型无法泛化到非字图形；把内容抽象成「中心线 + 动作先验」后，
同一个模型既能写汉字，也能写表格、箭头、示意图。这正是「全能」的统一方式。

## 理由

- **复用已验证链路**：G 代码与预览的「同一份版面」保证实机一致，风险最低。
- **SVG 是任意形状的通用输入**：用户可在 Illustrator / Inkscape / Figma 画好再导入，
  不必被软件内置的几种图形限制。
- **结构化生成降低手绘成本**：表格框线保持机械精确，文字部分走字形管线
  （未来替换为个人风格模型）。
- **训练目标统一**：一份数据多用，且模型天然覆盖非字内容。

## 后果

正面：

- 产品从「写字机」升级为「任意图形书写机」；数据一份多用；训练目标统一。

边界与代价：

- SVG 的 `<text>` **不描边**（字体轮廓转中心线不在本期范围）；文字应作为独立手写层叠加。
- 表格 / 思维导图里的文字当前用**标准字形骨架**；风格模型接入后替换为个人笔迹。
- 图形归一化到绘制框，纵横比保存在 `meta.boxAspect`，训练时据此还原比例。

后续：

- `shapes.py` 可继续扩展流程图、公式、更多矢量图元；
- 笔迹动态模型的实现另立 ADR。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 每类内容各写一套渲染 / G 代码 | 重复实现，且极易与预览不一致 |
| 只支持手绘图形（不做结构化生成） | 无法满足「规整表格」，用户仍要手画 |
| 逐字训练模型 | 无法泛化到非字图形，与「全能」诉求冲突 |
