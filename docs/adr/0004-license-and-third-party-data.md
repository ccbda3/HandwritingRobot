# 0004. 许可策略与第三方数据合规

- 状态：已接受
- 日期：2026-10-14

## 背景

本项目有双重目标：作为开源作品集公开，同时保留未来商业化的可能。
而它不可避免地会接触到许可条款各异的第三方数据与代码：

| 来源 | 许可 | 关键限制 |
|---|---|---|
| Qt | LGPL-3.0 | 动态链接即可闭源发布；**静态链接后闭源发布违规** |
| WriteLikeYou 训练数据 | 明确标注 **commercial use prohibited** | 不得商用 |
| CASIA-OLHWDB / SCUT-COUCH | 仅限非商业研究，需申请 | 不得商用 |
| Make Me a Hanzi | 派生自 Arphic PL 字体 | Arphic Public License 有 copyleft 传染性 |
| 用户本人的笔迹数据 | 用户所有 | 涉及个人生物特征，隐私敏感 |

## 决策

1. **本仓库代码采用 Apache-2.0。** 带显式专利授权，商业友好，允许闭源衍生。
2. **模型权重与训练数据独立声明许可**，不使用仓库根目录的 LICENSE。
   每个数据集/权重目录下放独立的 `LICENSE` 或 `NOTICE` 说明来源与限制。
3. **禁止提交受限数据集与用户笔迹数据到本仓库。** `.gitignore` 已忽略 `data/**` 下的
   全部 json/csv/npz/npy/png/jpg，仅保留 `data/README.md` 与 `.gitkeep`。
4. **Qt 动态链接。** 发布包必须让用户能够替换 Qt 库文件；禁止静态链接后闭源分发。
5. **不使用禁止商用的数据集训练发布版模型。** 研究阶段可以使用，但
   Release 附带或用于生成商业输出的模型权重，其训练数据必须许可清晰。
6. **用户笔迹数据默认只存本地。** 任何上传、云端训练、共享行为必须显式征得用户同意。

## 理由

- 许可问题是**事后无法补救**的：一旦发布了用受限数据训练的权重，撤回成本极高。
  在项目只有几行代码时把规则定清楚，成本接近于零。
- 用户笔迹是生物特征数据，隐私敏感度高于普通个人信息。
  把它提交进公开仓库是典型的、代价高昂的疏忽。
- Apache-2.0 相对 MIT 多出专利授权条款，对一个可能被商业公司使用的 AI 项目更稳妥。

## 后果

正面：许可风险前置清除；仓库可以安全公开；用户数据不会意外泄露。

负面：

- 数据获取更麻烦——需要自行申请 CASIA/SCUT 数据集，或只用许可宽松的数据
  （Make Me a Hanzi、自采数据、合成数据）。
- 论文中的实验若使用受限数据集，需要说明其非商业研究用途，且不能把训练权重随代码发布。
- 发布包需要处理 Qt 动态库的分发与替换说明。
